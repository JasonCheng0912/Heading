## 2.生成 / 更新 erpcmdb.yaml（两种方法二选一）

### 方法一：执行 Pipeline `ka_gen_cmdb`（推荐）
- 地址：http://ci.hddomain.cn/job/ka_gen_cmdb/
- 重跑后脚本会读取 `production/erp.csv` 重新生成 `containers / subsystems`，并把 `hosts` 段的新 IP 自动回填到 `containers[].c_id`（如 `10.230.247.2_card-server-proxy-service_production_1/2`）
- 前提：先把第 1.2 节的 `erpcmdb.yaml` 的 `hosts:` 段、`app.yaml` 版本号改好，job 才会按新值生成

### 方法二：直接手动替换 erpcmdb.yaml（不跑 job，等价）
- 适用场景：无法访问 Jenkins / 想快速改完即用的临时调整
- 直接编辑 `production/erpcmdb.yaml`，共改 2 处（hosts 段 + 两行 c_id）：

**① `hosts:` 段（修改前 → 修改后）**
```yaml
# 修改前
hosts:
- host_id: app-01
  host_name: app-prd01
  host_ip: 10.230.247.114
  host_sshport: 22
  host_user: root
  host_sshpwd: ''
  host_group: erp
  host_sudo: false

# 修改后（host_user 用客户提供的非 root 用户 mapp；10.230.247.2 即 Jira 目标机，如 114 才是正式机则 IP 不动，仅改 user/sudo/pwd）
hosts:
- host_id: app-01
  host_name: app-prd01
  host_ip: 10.230.247.2
  host_sshport: 22
  host_user: mapp
  host_sshpwd: <mapp用户密码>
  host_group: erp
  host_sudo: true
```

**② `containers[]` 两行 `c_id`（修改前 → 修改后，仅 IP 前缀 114→2）**
```yaml
# 修改前
  c_id: 10.230.247.114_card-server-proxy-service_production_1
  c_id: 10.230.247.114_card-server-proxy-service_production_2

# 修改后
  c_id: 10.230.247.2_card-server-proxy-service_production_1
  c_id: 10.230.247.2_card-server-proxy-service_production_2
```

- 版本 / 端口 / subsystems 健康检查路径已正确，**无需改**（与 job 生成结果一致）
- 注意：**日后若再跑 `ka_gen_cmdb`，会以 erp.csv 为准重新覆盖 containers**（c_id 的 IP 也会由 hosts 段重新回填），故 hosts 段仍是唯一需长期手工维护的地方

> 两种方法最终产物相同。方法一适合正式交付（留 jenkins 执行记录）；方法二适合临时/紧急改完即用。
