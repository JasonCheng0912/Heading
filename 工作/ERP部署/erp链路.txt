
首先整条是用户访问系统的完整流量链路。最起点是门店、办公人员的 PC 浏览器，用户输入域名走标准 HTTP 80 端口发起请求。
所有外网请求统一先打到公网负载均衡 SLB，SLB 只对外暴露 80 端口，
它会把全部流量转发到内网固定机器 172.16.0.61 上的 OpenResty 网关，网关本机监听 80 端口接收流量。
网关靠 hdpos.conf 配置里的 location 规则，匹配用户访问的 URL 路径，
   - 读取`develop分支 hdpos.conf`匹配URL路径；
```bash
proxy_pass    http://h6-crm-service;
```

比如访问 /crm、/ 报表、/pos 前端，区分不同业务模块。
 
匹配到对应路径后，网关会读取 upstream.conf 文件，找到每个业务对应的宿主机 38XXX 高位端口，

 - 根据配置转发至`upstream.conf`定义的本机服务端口， 
 
```bash  
 upstream h6-crm-service {
      server 172.16.0.61:38169;
}
``` 

把请求转发过去。


宿主机和 Docker 容器做了端口映射，宿主机 38XXX 端口会转发到容器内部的业务端口8080/

业务处理过程中，服务会在内网调用底层组件：用 Redis 做缓存提速、Oracle 存核心交易数据、

MySQL  、OSS  ，最后把处理结果原路返回给用户浏览器
